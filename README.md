# ProxyGuard 0.5.0

Windows 后台守护程序。监控目标程序的出口国家：当本机公网出口不在允许国家内（通常是 VPN 断开）时，立即为目标程序写入 Windows 防火墙出站阻断规则，并弹出窗口提示。默认目标是 `codex.exe` 与 `claude.exe`，0.5.0 起也可以自己选择任意 `.exe`。

0.5.0 新增：**自选目标程序**，以及**时区一致性启动**——出口 IP 稳定后，通过 ProxyGuard 启动目标程序，并让它读到的本地时区与出口 IP 所在地一致。

## 使用方式（安装即用）

1. 运行 `ProxyGuard_0.5.0_x64-setup.exe`，在 UAC 弹窗中点“是”。这是唯一需要的管理员授权：用于写入防火墙规则，并注册开机自启计划任务（最高权限，运行时不再弹 UAC）。
2. 安装完成后守护进程自动运行，托盘图标常驻。
3. 在面板中选择“允许的出口国家”（默认 US）。
4. 启动一次 Codex 或 Claude，程序路径会被登记，之后即使它们没在运行，阻断规则也会生效。
5. 需要守护其他程序时，在“目标程序”面板中添加（见下文“自选目标程序”）。

卸载时安装器会先删除本程序创建的所有防火墙规则，再删除计划任务。

## 行为

- 每 5 秒检测一次本机公网出口 IP（`api.ipify.org`），IP 变化时才查询国家（`ipwho.is`）。
- 国家不在允许范围：立即写入阻断规则，窗口弹出，显示“当前 VPN 已断开”。
- 国家恢复为允许范围：自动删除规则，目标程序恢复联网。
- 连续两次无法检测出口国家：按失败处理，阻断目标程序（防止在无法确认时泄露）。
- 出口稳定性：连续检测到同一个允许国家的出口 IP 计数，达到 3 次后开放时区一致性启动；一旦不在允许范围、检测失败或 IP 变化，计数重置。
- 关闭窗口只是隐藏到托盘，守护继续运行。托盘“退出”会停止守护，但已写入的阻断规则保留，直到下次启动重新判定。

## 自选目标程序（0.5.0）

在面板的“目标程序”里可以添加任意 `.exe`，三种方式：

- **浏览…**：打开 Windows 文件选择器，选择 exe。
- **从运行中的进程选择**：列出当前运行中、带有可执行路径的进程（Windows 目录和 ProxyGuard 自身已排除），支持按名称或路径筛选，点击即填入路径。
- **手动输入完整路径**，回车或点“添加”。

每个自选程序有两个独立开关：

| 开关 | 作用 |
| --- | --- |
| 断网时阻断 | 出口不在允许国家（或无法确认）时，为它写入防火墙出站阻断规则；恢复后自动删除。关闭开关或移除程序时，会立即撤销它已有的规则。 |
| 时区伪装启动 | 允许通过 ProxyGuard 带出口时区启动它（见下节）。 |

内置的 `codex.exe` / `claude.exe` 始终受阻断保护，不能移除。路径会做校验：必须是已存在的绝对路径 `.exe`，不能含 `" % & | < > ^ !` 等会破坏命令行的字符。自选程序同样会在卸载时随防火墙规则一并清理。

## 时区一致性启动（0.5.0）

很多程序会读取本机时区，并与出口 IP 的所在地对照。VPN 出口在美国而本机时区是 `Asia/Shanghai` 时，两者就不一致。ProxyGuard 的做法是：**用它启动目标程序时，只给该子进程设置 `TZ` 环境变量**，取值为出口 IP 所在地的 IANA 时区。

- **时区来源**：`ipwho.is` 返回的 `timezone.id`（对应出口 IP 的城市）；缺失或格式非法时，回退到该国家的主时区（例如 US → `America/New_York`）。
- **启用条件（出口稳定）**：必须在允许国家内，且连续 3 次检测到同一个出口 IP，面板才会显示“时区伪装就绪”，“以 xxx 启动”按钮才可点。出口不在允许范围、检测失败或 IP 刚变化时，一律不允许启动，避免时区与 IP 对不上。
- **IP 变化时**：重新匹配时区，并在事件里提示。已经启动的程序不会被改动，会在列表中标记“出口已变，需重启”，重启后才采用新时区。
- **权限**：守护进程是最高权限运行的，所以目标程序通过 `runas /trustlevel:0x20000`（基本用户权限）启动，不会继承管理员权限。**不会**在失败时退回到提权启动。
- **范围**：只影响通过 ProxyGuard 启动的那个进程。不修改系统时区，不修改注册表，不注入 DLL，不拦截或改写网络流量。

### 时区伪装的局限（请务必阅读）

- **只能伪装时区，伪装不了 IP。** 目标程序访问网络时使用的就是真实出口 IP，本机无法在不做 HTTPS 中间人的前提下改写它，本项目也不做。这个功能的目的只是让“本地时区”与“出口 IP”保持一致。
- **`TZ` 环境变量不是所有程序都认。** Node.js、Python、Go 及大多数跨平台程序会读取；直接调用 Windows API（`GetTimeZoneInformation`）的原生程序、以及部分基于 Chromium/Electron 的程序会忽略它，对这类程序没有效果。判断某个程序是否生效，需要在程序内自行验证。
- **只对启动时刻生效。** 程序已经在运行时，必须关闭后经 ProxyGuard 重新启动。
- **这不会改变目标服务对地区的判断规则**，也不保证通过其地区检查。服务商可能对受支持地区或使用方式有条款约定，请自行确认合规。
- 通过 `runas` 启动在部分受管设备上可能被组策略限制；失败时界面会显示 runas 的退出码，不会静默退回其他方式。

## 构建（需要 Windows）

需要 Node.js LTS、Rust（MSVC 工具链）、Microsoft C++ Build Tools、WebView2 Runtime。

```powershell
npm install
npx tauri icon .\app-icon.png   # 首次构建前生成 src-tauri/icons，源码包未包含图标
npm run desktop:build           # 产物位于 src-tauri\target\release\bundle\nsis\
```

## 已知边界（请务必阅读）

- **不是零泄露的内核级开关。** 检测有 5 秒间隔，规则写入需要几百毫秒，期间可能有流量通过。
- **已建立的 TCP 连接不一定被立即切断**，通常在连接重建时生效。
- **按程序路径阻断。** 只能覆盖已登记的 exe 本体（默认 `codex.exe` / `claude.exe`，加上自己添加的程序）。Claude Code 若以 `node.exe` 运行 CLI（npm 安装方式），无法按程序精确阻断，且不会为了它去阻断 node.exe（会误伤其他程序）。Claude 桌面版的子进程若路径不同，也不会被覆盖。
- **检测的是本机系统出口**，不是每个进程的实际出口。若目标程序绕过系统路由（例如自带代理），检测结果不能代表它的真实出口。
- **GeoIP 是数据库归属**，不等同于物理位置。
- **需要管理员权限运行**：如果以普通用户启动，防火墙写入会失败，界面会显示错误，不会误报为已阻断。
- **第三方服务**：公网 IP 与国家/时区查询分别发送到 `api.ipify.org` 和 `ipwho.is`。在受管设备上使用前请确认组织政策。
- 这是一个守护工具，不修改 WDAC、Defender 或任何系统安全策略。

## 与 0.4.0 的区别

- 目标程序不再只有 `codex.exe` / `claude.exe`：可通过文件选择器、运行中进程列表或手动输入添加任意 exe，并可逐个开关“断网时阻断”和“时区伪装启动”。
- 新增“出口稳定”判定和“时区一致性启动”（`TZ` 环境变量，仅作用于子进程）。
- 配置文件 `guard.json` 新增 `customTargets` 字段；旧版本配置可直接读取，无需迁移。
- 新增 Tauri 命令：`add_target`、`remove_target`、`set_target_flags`、`pick_file`、`list_processes`、`launch_target`。
- 本版本的源码改动在没有 Windows 与 Rust 依赖的环境中完成，只做了语法检查和前端类型检查，**尚未实际编译和运行**。构建后请先验证：添加程序、阻断/恢复、带时区启动三条路径。

## 与 0.3.0 的区别

0.3.0 是按“代理端点 + 软件组 + 每次 UAC”设计的原型。0.4.0 面向系统级 VPN，去掉了代理配置，只监控 Codex / Claude，改为安装时一次授权、后台常驻、开机自启。
